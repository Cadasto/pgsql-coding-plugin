# pgsql-migrations: zero-downtime schema changes

Scope: applying DDL to a PostgreSQL 18 table that live traffic reads and writes, so that no statement stalls that traffic or leaves the schema half-changed.

Deterministic backstop: `squawk 'migrations/*.sql'` on every migration file, with the config from `/pgsql-lint-setup`; each finding names a rule id from the [squawk rules](https://squawkhq.com/docs/rules). A clean squawk run is not a safe run: the migration still needs a lock timeout and a retry ([squawk: applying migrations safely](https://squawkhq.com/docs/safe_migrations)).

## Rules

- **Set `lock_timeout` before DDL that takes `ACCESS EXCLUSIVE`, `SHARE ROW EXCLUSIVE` or `SHARE`, and retry on timeout.** A statement waiting for a lock also blocks every later request that conflicts with it ([`pg_blocking_pids`](https://www.postgresql.org/docs/18/functions-info.html#FUNCTIONS-INFO-SESSION-TABLE)). An `ALTER TABLE` queued behind one long transaction therefore stops every `SELECT` on the table. `SET lock_timeout = '1s';` makes it fail fast instead; rerun until it succeeds ([`lock_timeout`](https://www.postgresql.org/docs/18/runtime-config-client.html#GUC-LOCK-TIMEOUT)). Add a `statement_timeout` too. squawk: `require-lock-timeout`, `require-statement-timeout`.
- **Give each slow step its own transaction.** A lock is held until the transaction ends ([13.3.1](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-TABLES)), so a quick `ACCESS EXCLUSIVE` step followed by a table scan in the same transaction holds the strong lock for the whole scan. squawk `constraint-missing-not-valid` flags `NOT VALID` and `VALIDATE CONSTRAINT` in one transaction.
- **Add constraints `NOT VALID`, then `VALIDATE CONSTRAINT` in a later migration.** `NOT VALID` works for foreign-key, `CHECK` and not-null constraints. Inserts and updates are checked from then on; only the scan of existing rows is skipped. Validation takes only `SHARE UPDATE EXCLUSIVE`, so reads and writes continue ([ALTER TABLE notes](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-NOTES)). squawk: `constraint-missing-not-valid`, `adding-foreign-key-constraint`.
- **Make an existing column NOT NULL after the backfill, through a `NOT VALID` not-null constraint (PG 18).** Deploy code that writes the column on every insert and update, backfill, then `ADD CONSTRAINT t_c_not_null NOT NULL c NOT VALID`, then `VALIDATE CONSTRAINT`. Added before the backfill, the constraint rejects every update of a row still NULL ([ADD CONSTRAINT](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-DESC-ADD-TABLE-CONSTRAINT)). A bare `SET NOT NULL` scans the table under `ACCESS EXCLUSIVE` ([SET NOT NULL](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-DESC-SET-DROP-NOT-NULL), [release notes 18](https://www.postgresql.org/docs/18/release-18.html)). squawk: `adding-not-nullable-field`.
- **Build, drop and rebuild indexes `CONCURRENTLY`, outside a transaction block.** A plain `CREATE INDEX` blocks writes for the whole build. `CONCURRENTLY` does not, but it cannot run inside a transaction block, and it waits for every older transaction. Set `lock_timeout = 0` in its file: a short `lock_timeout` aborts it on a busy system, while its waiting blocks no reads or writes (`lock-levels.md`). A failure leaves an `INVALID` index that still slows writes and that `IF NOT EXISTS` keeps; drop it before a rerun ([CREATE INDEX](https://www.postgresql.org/docs/18/sql-createindex.html#SQL-CREATEINDEX-CONCURRENTLY)). A partitioned table builds its index `ON ONLY` the parent, then per partition ([5.12.2.2](https://www.postgresql.org/docs/18/ddl-partitioning.html#DDL-PARTITIONING-DECLARATIVE-MAINTENANCE)). squawk: `require-concurrent-index-creation`, `require-concurrent-index-deletion`, `require-concurrent-reindex`, `ban-concurrent-index-creation-in-transaction`.
- **Create a unique or primary key from a concurrent index.** `CREATE UNIQUE INDEX CONCURRENTLY`, then `ADD CONSTRAINT ... UNIQUE USING INDEX` ([ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-DESC-ADD-TABLE-CONSTRAINT-USING-INDEX)). squawk: `disallowed-unique-constraint`, `adding-serial-primary-key-field`.
- **Know which change rewrites the table.** A volatile default, a stored generated column, an identity column, a domain with constraints, or a type change that is not binary coercible rewrites the table and its indexes under `ACCESS EXCLUSIVE`. A non-volatile default, a virtual generated column and `varchar(n)` to `text` do not ([ALTER TABLE notes](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-NOTES)). Turn a rewrite into a new column, a backfill and a switch. squawk: `adding-field-with-default`, `changing-column-type`.
- **Rename and drop in two deploys: expand, then contract.** While a deploy rolls out, the old application version still runs, and a rename or drop breaks it. Ship code that stops using the old name first; rename or drop in a later migration ([squawk `renaming-column`](https://squawkhq.com/docs/renaming-column), [`ban-drop-column`](https://squawkhq.com/docs/ban-drop-column)). `DROP COLUMN` is quick but frees no space until rows are rewritten ([ALTER TABLE notes](https://www.postgresql.org/docs/18/sql-altertable.html#SQL-ALTERTABLE-NOTES)).
- **Backfill in batches, one transaction per batch, outside the schema migration.** Row locks taken by `UPDATE` last until the transaction ends ([13.3.2](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS)), so one `UPDATE` over the whole table holds them all and can outrun `statement_timeout`. Walk the primary key in ranges ([squawk `adding-field-with-default`](https://squawkhq.com/docs/adding-field-with-default)).
- **Add an enum value in its own migration, before code writes it.** A value added inside a transaction block cannot be used until that transaction commits, and there is no `DROP VALUE` ([ALTER TYPE](https://www.postgresql.org/docs/18/sql-altertype.html)). Give `BEFORE` or `AFTER` when the order matters. squawk: `require-enum-value-ordering`.
- **Match the migration tool's transaction handling.** goose runs a file in one transaction unless the file carries `-- +goose NO TRANSACTION` ([goose annotations](https://pressly.github.io/goose/documentation/annotations/)). golang-migrate sends a file as one `Exec`, which PostgreSQL runs as one implicit transaction ([golang-migrate postgres](https://github.com/golang-migrate/migrate/blob/master/database/postgres/README.md)). A file that runs outside a transaction must be safe to rerun. squawk: `prefer-robust-stmts`, `transaction-nesting`.

Column types in new DDL (`prefer-identity`, `prefer-bigint-over-int`, `prefer-text-field`, `prefer-timestamptz`) belong to `pgsql-schema`. Which index to build belongs to `pgsql-indexing`; building it on a live table belongs here. Diagnosing lock waits in a running system belongs to `pgsql-performance`.
